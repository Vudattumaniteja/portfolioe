Fixing Spiky Outputs with HTML Previews

"Something that I learned when working with the video editing harness: in video editing particularly, the outputs are basically very spiky. So in order to overcome this spikiness, we have to create something like an HTML template, or actually any template. The main idea is very simple: the agent basically generates an HTML template showing what are the different scenes and how it will animate each and every scene. Before even rendering the full video or before even doing a render, it will show you what all it is doing at different transitions. Then what you can do is you can give some notes and etc., and then it will recreate the HTML template again and you will refine and repeat. To get consistently good results, we have to follow these kinds of workflows, and I found it myself. And the video qualities are amazing."

PROJECT 04

Sandcastle & Baton Demo

Autonomous Multi-Agent Orchestrator Eliminating Context Degradation
Agentic Systems CLI Architecture Git Automation CI Verification
01

Motive & Friction

"When an AI coding agent works through a multi-issue backlog in a single session, context degradation ruins accuracy. Terminal logs and file diffs from Issue #1 linger in the window. By Issue #3, that leftover noise pollutes the model's reasoning, causing hallucinated requirements, sluggish response times, and silent regressions on unrelated files."

02

What I Built

"Sandcastle (`sc`), a CLI orchestrator enforcing a single-issue context boundary. It queries GitHub for issues labeled `ready-for-agent` and `AFK`, then spawns an isolated AI worker with an empty context window for Issue #N. The worker implements the fix test-first, verifies local tests, creates a PR, auto-merges, closes the issue, and terminates. Then Sandcastle passes the baton to a clean worker for Issue #N+1."

03

The Hardest Part

"Managing dependencies and safety gates across autonomous runs. Sandcastle checks prerequisite blockers (`Blocked by #N`) so tasks never execute out of order. If a worker hits failing tests or ambiguous specs, the Blocker Protocol halts the baton, tags the issue `status blocked`, and posts diagnostic logs so broken code never gets pushed."

04

Proof & Impact

1 Issue / 1 Context Zero cross-task context pollution
4 Safety Gates OPEN, ready, AFK, unblocked

RESEARCH PAPER • EXTENSION ARCHITECTURE

E-VRAG-G: Grounded Query Decomposition for Long Video RAG

Extension to E-VRAG (Xu et al., 2025, arXiv:2508.01546v1)
arXiv Extension DINOv2 ViT-B/14 ITS Clustering Moondream 0.5B LLaVA-Video 7B Long Video RAG
01

The Problem: Caption-Imagination Gap

In standard E-VRAG, decomposed query captions are synthesized purely from the raw text query without inspecting video content: CH = PH(Q). For complex or implicit queries, the LLM is forced to "imagine" visual vocabulary, triggering severe semantic mismatches and retrieval failure during coarse pre-filtering.

02

What I Built: Grounded Decomposition

Grounded decomposition using DINOv2 visual clustering, ITS distinctive frame selection, and Moondream 0.5B to build an offline visual inventory Vg that constrains query captions to what is actually in the video: CH = PH(Q, Vg). Drop-in design: online retrieval and multi-view QA are completely untouched.

03

Measured Benchmark Results

Empirically validated across four primary long-video benchmarks (Video-MME: 65.5, MLVU: 70.4, NextQA: 84.4). Achieved LVB 64.2 (+0.8 over blind baseline) with exactly 0 per-query runtime cost by amortizing the visual inventory offline during video indexing.
